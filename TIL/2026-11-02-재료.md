export default function Login() {           // 서버 컴포넌트 ("use client" 없음)

### 두 방식 비교 (강사님 `form-action-vs-client-state` 자료)
| | `/client-login` | `/login` |
|---|---|---|
| 페이지 | 파일 전체 `'use client'` | 서버 컴포넌트 + 안에 `"use server"` 함수 |
| 폼 | `<form onSubmit>` | `<Form action={서버함수}>` |
| 제출 값 | `useState` 값 | 브라우저가 만든 **`FormData`** (input의 `name`이 키) |
| input `name` | 없음 | `name="userId"`, `name="password"` **필수** |
| 제출하면 | `preventDefault` → 브라우저 콘솔 | `POST /login` → 서버 함수 실행 → **터미널**에 로그 |

- `/login`도 화면 값은 `useState`로 관리함 (통제 컴포넌트). 차이는 **제출이 어디로 가느냐**
- 서버 함수는 **클라이언트 컴포넌트 안에서 만들 수 없음** → 서버 컴포넌트(page)에서 만들어 props로 내려보냄
- `"use server"`를 빼먹으면 함수가 클라이언트로 넘어가면서 에러
- `name`이 없는 input은 `FormData`에 안 들어감 → `formData.get`이 `null`

### 🔍 보충할 것
- HTML input vs React input: React에서 `value`를 주면 **통제 컴포넌트** → `onChange`로 상태를 바꿔야 글자가 써짐
- `next/form`의 `Form`: `action`이 **문자열이면 GET 이동(검색창)**, **함수면 서버 함수 실행**
- `async function`의 `async`는 `<script async>`와 전혀 다른 것 (함수가 Promise를 반환한다는 뜻)

### 코드 — Zod로 입력 검사 (`schema/loginSchema.ts`)
```ts
import { z } from "zod";

const loginSchema = z.object({
  userId: z.string().min(1, "아이디를 입력해 주세요."),
  password: z.string().min(1, "비밀번호를 입력해 주세요."),
});

// 필드 하나만 검사해서 메시지 돌려주기
function loginFieldMessage(field: "userId" | "password", value: string) {
  const result = loginSchema.shape[field].safeParse(value);
  if (result.success) return "";
  return result.error.issues[0]?.message ?? "";
}
```
```tsx
// LoginForm: 렌더마다 전체 검사 → 실패하면 버튼 비활성
const isValid = loginSchema.safeParse(payload).success;
<Button type="submit" disabled={!isValid}>Login</Button>
```

## 파트4 — 리다이렉션과 HTTP stateless (14:00~14:45)

### 필기
- 로그인 페이지 리다이렉션, HTTP stateless (14:49)

### 코드 — 서버 함수에서 API 호출 + 이동 (`14:52 feat: api fetch login & redirect`)
```tsx
async function handleSubmit(formData: FormData) {
  "use server";
  const userId = formData.get("userId");
  const password = formData.get("password");

  const response = await fetch("http://localhost:8080/api/v1/auth/login", {   // Spring 서버
    method: "POST",
    headers: { "Content-Type": "application/json" },     // ← 이게 없으면 415 에러
    body: JSON.stringify({ email: userId, password }),   // 폼 이름은 userId, API 키는 email
  });
  const data = await response.json();
  if (data.success) {
    redirect("/");        // next/navigation
  }
}
```
- **`Content-Type` 빠뜨린 실수**: 문자열 body는 기본이 `text/plain` → Spring이 `HttpMediaTypeNotSupportedException` → `application/json` 헤더 추가로 해결
- `redirect`는 내부적으로 에러를 던져서 그 뒤 코드를 멈춤 → `try/catch` 안에 넣으면 안 됨
- 이 시점엔 토큰을 저장하지 않고 이동만 함 → 메인에서는 로그인했는지 모름 → 파트5로 이어짐

### 코드 — "로그인중" 표시 (`useFormStatus`)
```tsx
function LoginSubmitButton({ isValid }: { isValid: boolean }) {
  const { pending } = useFormStatus();     // react-dom
  return (
    <Button type="submit" disabled={!isValid || pending} aria-busy={pending}>
      {pending ? "로그인중" : "Login"}
    </Button>
  );
}
```
- `useFormStatus`는 **`<form>` 안쪽 자식 컴포넌트**에서만 동작 → 그래서 버튼을 따로 뺌
- 16:12에 `<form>`을 서버 컴포넌트인 `LoginSection`으로 올리고 `LoginForm` 전체를 그 안에 넣음

### HTTP stateless
- HTTP는 요청 하나하나가 **독립적**. 서버는 이전 요청을 기억하지 않음
- 그래서 로그인에 성공해도, 다음 요청에서 "누구인지"를 다시 알려 줘야 함 → **쿠키·세션·토큰**이 필요한 이유

### 🔍 보충할 것
- `redirect`의 기본 동작: 서버 액션에서는 `push`(뒤로가기 가능), 다른 곳은 `replace`
- `email`에 빈 값이 가면 API가 `must not be blank`로 거절 → 응답 메시지를 화면에 보여 주는 코드는 아직 없음

// login/page.tsx 서버 함수 안
const cookieStore = await cookies();          // next/headers

  httpOnly: true,                              // JS(document.cookie)로 못 읽음 → XSS 방어

### 코드 — 모든 페이지에서 로그인 여부 알기
```tsx
// app/layout.tsx
<Suspense fallback={null}>
  <AuthShell>{children}</AuthShell>
</Suspense>

// component/providers/AuthShell.tsx — 서버 컴포넌트: 쿠키를 읽음
const accessToken = (await cookies()).get("accessToken")?.value ?? null;
return <AuthProvider accessToken={accessToken}>{children}</AuthProvider>;

// component/providers/AuthProvider.tsx — 클라이언트: Context로 나눠 줌
"use client";
const AuthContext = createContext({ accessToken: null, isLoggedIn: false });
export function AuthProvider({ accessToken, children }) {
  return <AuthContext.Provider value={{ accessToken, isLoggedIn: Boolean(accessToken) }}>{children}</AuthContext.Provider>;
}
export function useAuth() { return useContext(AuthContext); }

// component/atoms/LoginStatus.tsx — 헤더에 "로그인됨" 표시
const { isLoggedIn } = useAuth();
if (!isLoggedIn) return null;
return <span>로그인됨</span>;
```
- **서버가 쿠키를 읽고 → 클라이언트에 Context로 전달** 하는 구조 (`httpOnly`라 브라우저 JS는 직접 못 읽음)
- `LoginForm`은 이미 로그인 상태면 `useEffect` 안에서 `router.replace("/")` (렌더 중에 이동하면 안 됨)
- 쿠키 이름은 `providers/authCookie.ts`의 `ACCESS_TOKEN_COOKIE` 상수 하나로 같이 씀

### 🔍 보충할 것
- **쿠키 방식 vs 서버 세션 방식** (필기에 "바꾸기"라고 적어 둠)
  - 지금 코드: 토큰을 쿠키에 넣고, **쿠키가 있기만 하면** 로그인으로 봄 (토큰이 진짜인지 검사 안 함)
  - 서버 세션: 서버(DB/메모리)에 세션을 저장하고, 쿠키에는 세션 ID만. 요청마다 서버가 ID로 조회 → 강제 로그아웃 가능
  - 10/29 TIL의 "세션 vs JWT"와 연결
- **프록시(미들웨어)**: 페이지에 도착하기 전에 요청을 가로채서, 쿠키가 없으면 `/login`으로 보내는 방식. Next 16에서는 `middleware.ts` → `proxy.ts`로 이름이 바뀜 (공식 문서 확인). 오늘 코드에는 아직 없음
- `httpOnly`, `secure`, `sameSite` 각각 막아 주는 공격 (XSS, 도청, CSRF)

```ts
// app/api/auth/login/route.ts
const loginSchema = z.object({
  email: z.string().min(1, "이메일을 입력해 주세요."),
  password: z.string().min(1, "비밀번호를 입력해 주세요."),
});

export async function POST(request: Request) {
  const body = await request.json().catch(() => null);
  const parsed = loginSchema.safeParse(body);              // 서버에서 다시 검사
  if (!parsed.success) {
    return NextResponse.json({ success: false, message: parsed.error.issues[0]?.message }, { status: 400 });
  }
  const result = await userService.login(parsed.data);
  if (!result.ok) {
    return NextResponse.json({ success: false, message: result.message }, { status: 401 });
  }
  return NextResponse.json({ success: true, data: { accessToken: result.accessToken, ... } });
}
```
- 폴더 `app/api/.../route.ts`에 HTTP 메서드 이름(`GET`, `POST`)으로 함수를 export하면 API가 됨

### 코드 — 서비스 계층 (`service/userService.ts`)
```ts
// 비밀번호 저장: 소금(salt) + scrypt 해시
function hashPassword(password: string) {
  const salt = randomBytes(16).toString("hex");
  const hash = scryptSync(password, salt, 64).toString("hex");
  return `${salt}:${hash}`;
}
// 로그인할 때: 같은 소금으로 다시 계산해서 비교
function verifyPassword(password: string, stored: string) {
  const [salt, hash] = stored.split(":");
  const actual = scryptSync(password, salt, 64);
  return timingSafeEqual(actual, Buffer.from(hash, "hex"));   // 시간 차이로 정답 유추 못 하게
}

prisma.user.findMany({ select: publicUser, orderBy: { createdAt: "desc" } })  // 목록 (password 제외)
prisma.user.findUnique({ where: { email } })                                  // 이메일로 찾기
prisma.user.create({ data: { email, name, password: hashPassword(pw) } })     // 생성
```
- 라우트(요청·응답) / 서비스(로직) / `lib/prisma`(DB 연결)로 역할을 나눔
- 없는 이메일이든 틀린 비밀번호든 **같은 메시지**("이메일 또는 비밀번호가 올바르지 않습니다.") → 어느 쪽이 틀렸는지 알려 주지 않음

## TIL 쓸 때 핵심 후보
1. 로그인 두 방식: **`onSubmit` + `preventDefault`(브라우저에서 끝)** vs **`action` + `"use server"`(서버 함수가 `FormData` 받음)**
2. `FormData`는 input의 **`name`**으로 만들어짐. `name` 없으면 서버가 못 받음
3. 서버 함수는 서버 컴포넌트에서 만들어 props로 내려보냄 (클라이언트 컴포넌트 안에서 정의 불가)
4. Zod: 같은 스키마 문법으로 **클라이언트(버튼 on/off)**와 **서버(API 400 응답)** 양쪽에서 검사
5. `fetch`로 JSON 보낼 땐 `Content-Type: application/json` 필수 (없으면 `text/plain` → 415)
6. `useFormStatus`는 `<form>` **안쪽 자식**에서만 `pending`을 볼 수 있음
7. HTTP는 stateless → 로그인 유지를 위해 **쿠키**(`httpOnly`)에 토큰 저장, 서버가 쿠키 읽어 Context로 전달
8. Prisma: `schema.prisma` → `generate` → `prisma.user.findUnique()`. MongoDB는 `db push`
9. 비밀번호는 **소금 + 해시**로 저장하고, 비교는 `timingSafeEqual`
10. (내 실수 모음) `.env`에서 클러스터 주소 지움, DB 이름 불일치, 잘린 해시 복사, Compass `$date` 형식
