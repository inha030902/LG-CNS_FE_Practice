## 파트2 — SOLID, 스크롤, 무한 스크롤의 새로고침 문제 (10:30~11:30)

### 필기 (10:04~11:30)
- SOLID 원칙(로버트 마틴). 프론트에서는 **S, O, I**를 많이 지키려고 함
  - L(리스코프 치환)은 상속 이야기라서, 함수로 짜는 React와 Next에서는 거의 의미가 없음
  - D(의존성 역전)도 크게 의미가 없음
  - 프론트는 객체지향보다 함수형으로 짜기 때문에 S, O, I가 중요함
- 함수형 코딩: 순수 함수, 불변성, 선언형 프로그래밍
- Next와 React의 스크롤 차이: Next는 페이지가 바뀌어도 스크롤 위치가 그대로이고, React는 다시 맨 위로 올라감
- 무한 스크롤 동작 방식 확인. **3페이지에서 새로고침하면 1, 2페이지가 다 사라짐**. 해결 방법:
  1. 새로고침했을 때 3페이지라면, 위로 스크롤하면 2페이지를 불러오게 처리 + `hasPreviousPage`로 판단
  2. 지금 스크롤한 위치가 몇 페이지인지 판단
- 채팅 구현 방식 설명(WebSocket 방식)
- 프리렌더링, 프리패칭으로 느려지는 문제 해결

### 코드 — 1단계: 아래로만 붙이기 (11:02 `fix: infinity scroll`)
- `PostInfinityScrollList.tsx`(클라이언트 컴포넌트)를 새로 만듦. 목록 끝에 빨간 `데이터 로딩중...` 박스(`bg-red-500`)를 두고 `IntersectionObserver`로 지켜봄
- 박스가 보이면 `router.push("/posts?page=N+1...", { scroll: false })`로 **주소만 바꿈**. 그러면 서버 컴포넌트가 그 페이지 20개를 다시 그려 props로 내려주고, 클라이언트는 `useState` 배열 뒤에 붙임
- 브라우저가 `fetch`로 다음 페이지를 직접 가져오지 않는다는 점이 핵심. 데이터는 여전히 서버(`getCachedPosts` → Prisma)가 줌
- props가 바뀐 걸 `useEffect`가 아니라 **렌더 중에 `setState`** 해서 맞춤(React 문서의 "prop이 바뀔 때 state 조정하기")
- 같은 커밋에서:
  - 5초마다 `router.refresh`하던 `PostLiveRefresh`를 지우고, 새 글이 생기면 알려 주는 SSE로 바꿈

  - `insert`가 오면 `revalidateTag("posts")` 후 브라우저가 `router.refresh()`
- 이 방식의 문제가 필기의 "3페이지에서 새로고침하면 1, 2페이지가 사라짐". 주소가 `?page=3`이라 서버는 3페이지만 그림

### 코드 — 2단계: 위로도 붙이기 (11:25 `fix: infinity scroll step2`)
- 배열 하나 대신 **페이지 묶음**(`groups: [{ page, posts }]`)으로 바꿈. 맨 앞 페이지와 맨 뒤 페이지를 알 수 있게 하려고

- 홈 화면의 글 불러오기를 `HomePosts.tsx`로 따로 빼서 `<Suspense>` 안에 넣음 → "프리렌더링으로 느려지는 거 해결"과 관련 있어 보임 (🔍 확인 필요)

### 🔍 보충할 것
- **SOLID의 S, O, I를 컴포넌트로 말하면**
  - S(단일 책임): 한 컴포넌트, 훅은 한 가지 일만. 오늘 3단계에서 훅을 셋으로 나눈 것이 예
  - O(개방-폐쇄): 기존 코드를 고치지 않고 props나 children으로 확장
  - I(인터페이스 분리): 컴포넌트가 쓰지도 않는 props를 받지 않게
- **D는 오늘 오후 코드에 오히려 나옴**: `authPort`(규칙)에 의존하고 실제 구현(Spring, Prisma)은 갈아끼우는 구조가 의존성 역전임. "프론트에서 크게 의미 없다"와 오후 코드의 관계를 내 말로 정리해 보기
- **Next와 React의 스크롤 차이**: Next `Link`와 `router.push`는 기본으로 새 페이지의 맨 위로 스크롤함. 그래서 무한 스크롤에서는 `{ scroll: false }`로 위치를 지킴. 필기의 "Next는 고정"이 이 옵션 이야기인지, 레이아웃이 다시 그려지지 않는 이야기인지 확인 필요
- **프리렌더링·프리패칭**: `next.config.ts`에 `cacheComponents: true`, `partialPrefetching: true`가 켜져 있음. 오늘 강사님이 말한 해결이 이 설정인지, `<Suspense>`로 나눈 것인지 확인

### 코드 — `reducePostPageWindow`의 판단 순서
1. 검색 조건(`정렬:검색어`)과 받은 페이지 글 id가 같으면 → 그대로
2. 검색 조건이 바뀌면 → 한 페이지로 새로 시작
3. 이미 있는 페이지 번호면 → 그 페이지 글만 교체
4. 맨 뒤 + 1이면 → 뒤에 붙임
5. 맨 앞 − 1이면 → 앞에 붙임
6. 그 외(점프)면 → 한 페이지로 새로 시작

### 코드 — 처음 열자마자 이전 페이지를 부르지 않게
- `IntersectionObserver`는 관찰을 시작하는 순간 이미 보이는 요소에도 콜백을 한 번 부름. 그래서 3페이지로 새로고침하면 위 박스가 바로 보여서 2페이지를 곧장 불러 버릴 수 있음
- 막는 장치는 `armPreviousRef`(처음 값 `false`). 사용자가 실제로 위로 스크롤하거나(`scrollY` 감소), 휠을 위로 굴려야(`deltaY < 0`) 깃발이 올라감
- 아래로 붙일 때는 이런 장치가 없음. 첫 화면에 빨간 박스가 보이면 바로 다음 페이지를 부름

### 🔍 보충할 것
- **`useEffect`와 `useLayoutEffect`**: `useLayoutEffect`는 화면에 그리기 전에 실행됨. 스크롤 보정을 `useEffect`로 하면 밀린 화면이 한 프레임 보였다가 돌아감
- **`{ passive: true }`**: 스크롤 리스너 안에서 `preventDefault()`를 안 하겠다는 약속. 브라우저가 기다리지 않고 바로 스크롤할 수 있음
- **로직은 순수 함수로, 화면은 훅으로**: `postPageWindow.ts`는 React 없이 테스트할 수 있음. 오전 필기의 "순수 함수, 불변성"이 코드로 나온 예(배열을 고치지 않고 `[...groups, 새 페이지]`로 새로 만듦)

  - `.env.local`: 비밀 값(DB, NextAuth 비밀키, 카카오·구글 키). 어느 모드에서든 읽힘
  - 우선순위: 실제 환경 변수 > `.env.$(NODE_ENV).local` > `.env.local` > `.env.$(NODE_ENV)` > `.env`

  - 모든 `.env*` 파일은 `.gitignore`에 걸려 GitHub에 안 올라감 → 강사님 파일도 GitHub에서 볼 수 없었던 이유
