### 코드 — 인증 설정 (`lib/authOptions.ts`, `main` 최종)
```ts
export const authOptions: NextAuthOptions = {
  secret: process.env.NEXTAUTH_SECRET,
  session: { strategy: "jwt", maxAge: 60 * 60 * 2 },   // 2시간
  pages: { signIn: "/login" },
  providers: [
    CredentialsProvider({
      name: "Credentials",
      credentials: {
        email: { label: "Login ID", type: "text" },
        password: { label: "Password", type: "password" },
      },
      async authorize(credentials) {
        if (!credentials?.email || !credentials?.password) return null;
        const result = await userService.login({
          email: credentials.email,
          password: credentials.password,
        });
        if (!result.ok) return null;                    // null이면 로그인 실패
        return {
          id: result.user.id,
          email: result.user.email,
          name: result.user.name ?? "",
          accessToken: result.accessToken,
          expiresIn: result.expiresIn,
        };
      },
    }),
  ],
  callbacks: {
    async jwt({ token, user }) {
      if (user) {                                       // 로그인 직후에만 user가 있음
        token.accessToken = user.accessToken;
        token.expiresIn = user.expiresIn;
        token.id = user.id;
      }
      return token;
    },
    async session({ session, token }) {
      session.accessToken = token.accessToken ?? "";
      session.expiresIn = token.expiresIn ?? 60 * 60 * 2;
      session.user = { id: token.id ?? "", email: token.email ?? "", name: token.name ?? "" };
      return session;
    },
  },
};
```
- 값이 이동하는 순서: **`authorize`의 반환값 → `jwt`의 `user` → `token` → `session`**
- 10:48 버전은 `user.user`만 돌려줘서 `accessToken`이 없었음 → 11:06에 고침

### 코드 — 단계마다 서버가 처리 (`15:17 fix: server action`)
```ts
// app/(auth)/signup/actions.ts
export async function submitSignupPassword(formData: FormData) {
  const draft = await readSignupDraft();
  await ensureReached(draft, 2);                   // 앞 단계를 통과했는지 확인
  const password = readText(formData, "password");
  const parsed = signupPasswordSchema.safeParse(password);
  if (!parsed.success) {
    await writeSignupDraft({ ...draft, password, passwordOk: false, step: 2 });
    await writeSignupErrors({ password: parsed.error.issues[0]?.message ?? "비밀번호는 8자 이상이어야 합니다." });
    redirect("/signup");
  }

  await writeSignupDraft({ ...draft, password: parsed.data, passwordOk: true, step: 3 });
  await writeSignupErrors({});
  redirect("/signup");
}
```
```tsx
// app/(auth)/signup/page.tsx — 서버가 쿠키를 읽어 현재 단계를 그림
async function SignupContent() {
  const draft = await readSignupDraft();
  const errors = await readSignupErrors();
  const maxStep = furthestSignupStep(draft);
  const step = draft.step > maxStep ? maxStep : draft.step;   // 건너뛰기 방지
  return <SignupSection step={step} draft={draft} errors={errors} />;
}
```
흐름: **제출 → 서버 검증 → 값·오류를 쿠키에 저장 → `redirect("/signup")` → 서버가 쿠키를 읽어 다시 렌더링**

- `signup-draft`, `signup-errors` 쿠키 사용 (`httpOnly`, 30분)
- `furthestSignupStep`: 통과한 단계를 계산해서 건너뛰기를 막음
- 폼 4개로 분리: `SignupIdentityForm`, `SignupPasswordForm`, `SignupInterestsForm`, `SignupProfileForm`
- 입력칸은 폼 태그 밖에 있고 `form={FORM_ID}` 속성으로 연결 (폼 중첩을 피하려는 구조로 보임)
- `value` + `onChange`(통제)에서 `defaultValue`(비통제)로 변경 → 입력마다 상태를 바꾸지 않음
- `useFormStatus`로 `SignupSubmitButton`에 "확인 중" 표시
- `try` 안에서 `redirect`가 잡히지 않도록 `catch`에서 `unstable_rethrow(error)` 호출 → 어제 배운 "`redirect`는 에러를 던진다"와 연결

### 코드를 읽으며 발견한 것
- ⚠ 비밀번호가 **평문으로 쿠키에 최대 30분** 저장됨. `httpOnly`라 JS로는 못 읽지만 암호화는 아님 → 실제 서비스에서는 피해야 함
- 사진은 쿠키에 저장하지 않고 마지막 단계에 `multipart/form-data`로 전송

### 🔍 보충할 것

### 코드 — `searchParams`로 단계 읽기 (`16:50 fix: server side rendering form`)
```tsx
// app/(auth)/signup/page.tsx
export default async function SignupPage({ searchParams }: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>;
}) {
  const searchParamsData = await searchParams;       // Promise라서 await
  const step = searchParamsData.step === undefined ? 1 : parseInt(searchParamsData.step as string);

  return (
    <Suspense fallback={<SignupFallback />}>
      <Link href={`/signup?step=${step + 1}`}>next</Link>
      <Link href={`/signup?step=${step - 1}`}>previous</Link>
      <SignUpFormSection step={step} handleSignup={handleSignup} />
    </Suspense>
  );
}
```


## 파트7 — useEffect 없는 코드, 숙제 (16:45~17:50)

### 필기
- 전체적으로 코드가 useeffect가 사용되지 않았음. 트리거가 없음. developer 계정 만들어오기. auth 사용시 app -> api -> auth -> [...nextauth] (17:02)

### 코드 확인
- 회원가입의 단계 이동과 데이터 처리는 `useEffect` 없이 서버 액션, `redirect`, URL로 동작
- 11:26 커밋에서 `LoginForm`의 `useEffect` 리다이렉트도 서버 `redirect`로 바뀜

- ⚠ `main`의 `LoginForm`에는 아직 `useEffect`가 남아 있음 (브랜치에서만 제거됨)

### 🔍 보충할 것
- 필기의 **"트리거가 없음"** 뜻 확인 (렌더링 후 effect로 다음 동작을 일으키는 코드가 없다는 뜻으로 보임)
- 공식 문서 "You Might Not Need an Effect"와 연결
- **developer 계정**: 어느 서비스의 계정인지 필기에 없음 → 강사님 안내 확인 (OAuth 실습용일 가능성 있음)

## 최종 로그인 흐름 (`main` 기준)
```
[브라우저] /login 입력 (LoginForm: useState + Zod로 버튼 on/off)
   │ onSubmit → signIn("credentials", { email, password, redirect: false })
   ▼
[next-auth] /api/auth/[...nextauth] → authorize(credentials)
   │ userService.login
   ▼
[MongoDB Atlas] prisma.user.findUnique({ where: { email } }) → verifyPassword (scrypt)
   │ 성공 → jwt 콜백이 token에 accessToken, id 저장
   ▼
[쿠키] next-auth가 세션 토큰 쿠키 저장
   │ router.replace("/") + router.refresh()
   ▼
[다음 요청] AuthShell → getServerSession → session 콜백 → AuthProvider(isLoggedIn) → 헤더 "로그인됨"
```
