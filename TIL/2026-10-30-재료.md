### 호이스팅
| 선언 | 선언 줄보다 앞에서 쓰면 |
|---|---|

| `import` | 모듈 본문이 실행되기 **전에** 먼저 연결됨 |

### 코드 — `cn` 함수 (`10:45 feat: dynamic route`, `lib/utils.ts`)
```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```
- `clsx`: 조건부로 클래스를 모아 줌 (`clsx("a", isOpen && "b", { c: isActive })`)
- `twMerge`: 그 결과에서 **겹치는 Tailwind 클래스는 뒤의 것만 남김** (어제 `CustomTitle`에서 쓴 것)
- `cn` = 둘을 합친 것 → "조건부로 모으고 + 충돌 정리"
- (참고) 15:17 shadcn을 설치한 뒤에는 `lib/utils.ts`가 `export { cn } from "cn"` 한 줄로 바뀜 (강사님 쪽도 같음)

### 코드 — 동적 라우트 첫 버전 (`10:45`)
```
app/(main)/blog/[blogId]/page.tsx   → /blog/아무거나
```
```tsx
export default async function BlogPage({
  params,
}: {
  params: Promise<{ blogId: string }>
}) {
  const { blogId } = await params      // /blog/name 이면 "name"
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <BlogContent blogId={blogId} />
    </Suspense>
  )
}
```
- 폴더 이름을 `[이름]`으로 쓰면 그 자리는 **아무 값이나 받는 칸**이 되고, `params.이름`으로 꺼냄
- Next 15부터 `params`는 **Promise** → `await` 해야 함
- (이 코드는 13:50에 `await` 위치가 바뀜 → 파트3 참고)

### CSR vs SSR — "주소가 먼저냐 그림이 먼저냐"
| | CSR (`lgcns-fe`, Vite React) | SSR (`lgcns-fe-next`) |
|---|---|---|
| 첫 HTML | `<div id="root">`가 **비어 있음** | 서버가 이미 그린 HTML |
| 먼저 바뀌는 것 | **그림(상태)이 먼저**. `useState`로 page를 1 올리면 화면만 바뀜 | **주소가 먼저**. `/feed?page=2`로 이동 → 서버가 그 주소를 보고 다시 그림 |
| 새로고침하면 | `useState` 초기값으로 돌아감 (page가 1로 리셋) | 주소에 page가 있으니 그대로 유지 |
| 라우팅 | `BrowserRouter` + `<Route>` | 폴더 = 주소 |

### 🔍 보충할 것
- 같은 "다음 페이지" 버튼을 CSR 방식(`useState`)과 SSR 방식(`router.push`로 주소 변경)으로 둘 다 만들어 보면 차이가 확실해짐 → 파트4 `FeedNextButton`이 SSR 쪽 예
- 상태를 주소에 두면 좋은 점: 새로고침·공유·뒤로가기가 그대로 동작

### DOM과 BOM 정리
| | DOM | BOM |
|---|---|---|
| 뜻 | Document Object Model. **문서(HTML) 내용** | Browser Object Model. **브라우저 창 자체** |
| 시작점 | `document` | `window` |
| 예 | `document.querySelector`, `element.addEventListener` | `location`, `history`, `navigator`, `screen`, `alert` |

- 주소창 관리 = BOM의 `location`, `history`
  ```js
  location.href            // 현재 전체 주소
  location.search          // "?page=1&limit=10"
  new URLSearchParams(location.search).get("page")  // "1"
  location.href = "/feed?page=2"                   // 이동 (새로 불러옴)
  history.pushState({}, "", "/feed?page=2")        // 주소만 바꿈 (새로 안 불러옴)
  ```
- Next의 `router.push`, React Router의 `navigate`는 내부적으로 `history.pushState`를 씀 → 페이지를 통째로 다시 안 불러오고 주소만 바꿈

### 코드 — `await`를 Suspense 안으로 (`13:50 fix: dynamic route`)
```tsx
// app/(main)/blog/[blogId]/page.tsx — async 제거, Promise를 그대로 넘김
export default function BlogPage({ params }: { params: Promise<{ blogId: string }> }) {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <BlogContent params={params} />
    </Suspense>
  )
}

// component/templates/BlogContent.tsx — 여기서 await
export default async function BlogContent({ params }: { params: Promise<{ blogId: string }> }) {
  const { blogId } = await params
  return <div><h1>Blog Page</h1><p>{blogId}</p></div>
}
```
- 왜 옮겼나: `next.config.ts`에 `cacheComponents: true`가 켜져 있음. 이때 **Suspense 밖에서 `await params`를 하면 프리렌더가 막혀 에러**가 남
- 바꾼 뒤: 페이지 껍데기(정적)는 먼저 나가고, `await`가 필요한 부분만 `Loading...` → 값이 오면 채워짐

### 코드 — catch-all 라우트 (`13:50`, `14:06 fix: product`)
```
app/(main)/product/[...productCategoryName]/page.tsx
```
| URL | `productCategoryName` | `.join("/")` |
|---|---|---|
| `/product/laptop` | `["laptop"]` | `laptop` |
| `/product/laptop/gram` | `["laptop", "gram"]` | `laptop/gram` |
| `/product` | 매칭 안 됨 (404) | — |

| 폴더 표기 | 받는 값 |
|---|---|
| `[blogId]` | 한 칸, `string` (`/blog/a/b`는 안 맞음) |
| `[...name]` | 여러 칸, `string[]` (최소 한 칸 필요) |
| `[[...name]]` | 여러 칸 + **없어도 됨** (없으면 `undefined`) |

- 14:06에 블로그와 똑같이 `ProductPage`(Suspense) + `ProductContent`(await) 구조로 나눔

### 코드 — Tailwind 동적 클래스 (같은 커밋의 정리 자료)
```tsx
className={`bg-${color}-600`}                    // ❌ 안 됨: 소스에 "bg-red-600"이 없음
className={isOpen ? "block" : "hidden"}           // ✅ 됨: 완성된 이름 중 고르기만 함
const colors = { red: "bg-red-600", blue: "bg-blue-600" }
className={colors[color]}                         // ✅ 공식 문서 권장 방식
```
- Tailwind는 **소스 코드를 글자로 훑어서** 보이는 클래스 이름만 CSS로 만듦. 실행 중에 조립된 이름은 모름
- `cn`/`twMerge`는 실행 중에 합치기만 할 뿐, CSS를 만들어 주지 않음
- 꼭 써야 하면 `@source inline("bg-{red,blue}-600")`으로 미리 생성

### 코드 — 피드 페이지 (`14:47 feat: feed searchParams를 Suspense 안에서 읽는다`)
```tsx
// app/(main)/feed/page.tsx — 서버 컴포넌트, await 없음
export default function FeedPage({ searchParams }: {
  searchParams: Promise<{ page: string; limit: string; sort: string; search: string }>
}) {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <FeedContent searchParams={searchParams} />
    </Suspense>
  )
}

// component/templates/FeedContent.tsx — 서버 컴포넌트, 여기서 await
export default async function FeedContent({ searchParams }) {
  const { page, limit, sort, search } = await searchParams
  return (
    <div className="flex flex-col gap-4 p-4">
      <h1>Feed Page</h1>
      <p>page: {page}</p>
      ...
      <FeedNextButton page={page} limit={limit} sort={sort} search={search} />
    </div>
  )
}
```
```tsx
// component/molecules/FeedNextButton.tsx — 클라이언트 컴포넌트
"use client"
import { useRouter } from "next/navigation"

export default function FeedNextButton({ page, limit, sort, search }) {
  const router = useRouter()
  return (
    <button onClick={() => {
      router.push(`/feed?page=${parseInt(page) + 1}&limit=${limit}&sort=${sort}&search=${search}`)
    }}>
      Next
    </button>
  )
}
```
- 흐름: 버튼 클릭(브라우저) → **주소를 바꿈** → 서버가 새 주소의 `searchParams`를 읽어 다시 그림 → 파트2 "주소부터 바꾸는 건 SSR"의 실제 예
- **서버 컴포넌트 안에 클라이언트 컴포넌트를 넣을 수 있음** (`FeedContent` → `FeedNextButton`). 클릭이 필요한 버튼만 `"use client"`
- `useRouter`는 `next/router`가 아니라 **`next/navigation`**에서 가져옴 (App Router)

### params vs searchParams
| | `params` | `searchParams` |
|---|---|---|
| 위치 | 경로 `/blog/name`의 `name` | 쿼리 `?page=1`의 `page` |
| 정하는 곳 | 폴더 이름 `[blogId]` | 주소를 여는 쪽 (폴더와 무관) |
| 타입 | `string` 또는 `string[]` | `string`, 같은 키 반복이면 `string[]`, 없으면 `undefined` |
| 공통 | Promise → `await`, Suspense 안에서 | 〃 |

### 🔍 보충할 것
- **server action vs client action**: 오늘 코드엔 server action(`"use server"`)이 아직 없음. 정의 찾아보기
  - Server Action: `"use server"` 함수. 브라우저에서 호출하지만 **서버에서 실행** (폼 제출, DB 저장 등)
  - 클라이언트 쪽 동작: `onClick` 같은 이벤트 핸들러. 브라우저에서 실행
- `/feed`처럼 쿼리 없이 들어오면 `page`가 `undefined` → `parseInt(undefined) + 1` = `NaN` → 기본값 처리 필요 (`page ?? "1"`)
- 쿼리 문자열을 템플릿으로 직접 만들면 `search`에 `&`, 한글 등이 들어갈 때 깨짐 → `URLSearchParams`로 만드는 게 안전

### 코드 — shadcn `Button`의 구조 (`components/ui/button.tsx`)
```tsx
import { Button as ButtonPrimitive } from "@base-ui/react/button"
import { cva, type VariantProps } from "class-variance-authority"

const buttonVariants = cva("inline-flex items-center ... (기본 클래스)", {
  variants: {
    variant: { default: "bg-primary ...", outline: "...", ghost: "...", destructive: "...", link: "..." },
    size:    { default: "h-8 ...", sm: "h-7 ...", lg: "h-9 ...", icon: "size-8" },
  },
  defaultVariants: { variant: "default", size: "default" },
})

function Button({ className, variant = "default", size = "default", ...props }) {
  return <ButtonPrimitive className={cn(buttonVariants({ variant, size, className }))} {...props} />
}
```
- `cva`: `variant`/`size` 값에 따라 **미리 적어 둔 완성된 클래스**를 골라 줌 → 파트3 "동적 클래스는 맵으로" 방식 그대로
- 마지막에 `cn`으로 밖에서 넘긴 `className`을 합침 → 겹치면 밖의 값이 이김
- shadcn은 라이브러리를 import하는 게 아니라 **코드를 내 프로젝트에 복사** → `button.tsx`를 직접 고쳐도 됨
