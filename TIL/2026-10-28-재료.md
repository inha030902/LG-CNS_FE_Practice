## 파트1 — HTML 구조와 시맨틱 (09:10~10:20)

### 필기
- html head 설명. `<meta>` 태그 ex) og
- html은 body에 있어야 할 내용이 head에 있더라도 자동 보정이 됨. `</p>` 등 닫는 태그를 빼도 어느 정도 자동으로 보정해서 브라우저에서 열림.
- 전통적인 css의 문제점: 코드에 종속을 걸음.
- scss, sass는 각광받다가 지금은 거의 안 씀.
- **구조로 해결할 수 있는 걸 소스 코드로 해결하지 마라.** (AI랑 같이 개발하기 때문에)
- h1과 a의 관계: a를 감싼 것에 h1을 넣을 거냐, h1으로 감싼 것에 a를 넣을 거냐.
- p 안에 div를 넣으면 p의 정의와 맞지 않음. 코드상 에러는 안 나지만, p 안에는 span을 넣음.
- section element

### 코드 — `index.html`의 head
```html
<html lang="ko-KR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="테스트 페이지">
    <meta property="og:title" content="테스트 페이지">
    <meta property="og:description" content="테스트 페이지">
    <meta property="og:image" content="https://...googlelogo_color_272x92dp.png">
    <meta property="og:url" content="https://www.google.com">
    <meta property="og:type" content="website">
    <!-- og:twitter:* 등 생략 -->
    <title>Document</title>
</head>
```

### 🔍 보충할 것
- og(Open Graph) 태그가 쓰이는 곳: 카톡·슬랙 등에 링크를 붙였을 때 뜨는 미리보기 카드
- "전통 CSS가 코드에 종속을 건다"는 게 구체적으로 무슨 뜻인지 (전역 스코프, 클래스명 충돌 등?)
- 블록 요소와 인라인 요소의 차이 → p 안에 div가 안 되는 이유
- section, article, header, nav 같은 시맨틱 태그를 언제 쓰는지

## 파트2 — form과 CSS 기초 (10:30~11:30)

### 필기
- button과 div의 차이
- 라디오는 기본 속성을 지켜야 함. 보이는 것만 생각해서 div로 만들면 기본 속성이 사라짐. 기본 속성을 따르면 같은 그룹으로 묶여서 5개 중 1개만 선택되는데, div로 만들면 이게 안 됨.
- `<form>`
- css font: em, rem 차이를 알면 좋음
- placeholder, display flex, grid

### 코드 — 로그인 폼 (`index.html`)
```html
<form action="" method="post">
    <input type="text" class="input01" name="id" placeholder="ID">
    <input type="password" class="input01" name="password" placeholder="Password">
    <input type="email" class="input01" name="email" placeholder="Email">
    <button type="button" class="mybtn" onclick="login()">LOGIN</button>
</form>
```
```js
function login() {
    const id = document.querySelector('.input01').value;
    const password = document.querySelector('.input01').value;  // ⚠ 둘 다 첫 번째 input을 가리킴
    console.log(id, password);
}
```

### 코드 — CSS 변수 (`css/color.css`, `css/font.css`)
```css
:root {
    --color-primary: skyblue;
    --font-primary: 'Roboto', sans-serif;
}
```

### 🔍 보충할 것
- button과 div의 차이: 키보드 포커스, Enter/Space 동작, 스크린리더, form 제출
- 라디오 그룹은 `name`이 같아야 묶임
- `button type="button"`과 `type="submit"`의 차이
- em(부모 기준)과 rem(루트 html 기준)
- flex(1차원)와 grid(2차원)
- `querySelector`는 첫 번째 요소 하나만 반환함 → 위 login()에서 password도 id 값이 나옴

## 파트5 — CSS 애니메이션과 반응형 (15:15~16:00)

### 필기
- media 쿼리를 잘 작성해야 됨. Tailwind와 반대 방향으로 짤 수도 있음
- 모바일에서는 width를 100%로 맞추고 보통 아래로 내림. 즉 화면을 키우면서 바뀌는 걸 맞춤(모바일 우선). Tailwind도 이렇게 함. ex) `sm:col-12`
- css transition의 역할
- css border, margin 설명

### 코드 — 버튼 hover 테두리 애니메이션 (`App.css`)
```css
@property --orbit {            /* 각도를 애니메이션할 수 있는 CSS 변수 */
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

.counter::before {
  background: conic-gradient(from var(--orbit), transparent 0deg, transparent 230deg,
              #ff9af5 300deg, #fff 332deg, #ff00fb 360deg);
  opacity: 0;
  transition: opacity 0.25s ease;   /* 나타날 때 부드럽게 */
}
.counter:hover::before {
  opacity: 1;
  animation: counter-orbit 1.2s linear infinite;
}

@keyframes counter-orbit {
  to { --orbit: 1turn; }
}

@media (prefers-reduced-motion: reduce) {   /* 움직임 줄이기 설정한 사용자 배려 */
  .counter:hover::before { animation: none; }
}
```

### 🔍 보충할 것
- transition과 animation의 차이: 상태 변화 사이를 보간 vs keyframes로 정의한 움직임
- 모바일 우선(`min-width`)과 데스크톱 우선(`max-width`) media 쿼리 비교
- box model: content → padding → border → margin
